# v0.2.2 隐私与威胁边界

引擎和默认 MCP 服务本地运行，无外网客户端、API、遥测或模型采样。默认通过标准输入输出通信，不打开浏览器或监听端口。Codex 管理本地 MCP 子进程的生命周期；它不是系统服务。显式启用的旧浏览器兼容模式才短暂监听 127.0.0.1。

检查不会执行待检命令、不上传文本，不自动读取 transcript_path 或所有引用文件。有界脚本检查只读取已支持的脚本及简单本地引用。原生表单只展示规则与按启用规则脱敏的摘要，要求本次选择及可选原因，不收集凭据。

默认保留最近 100 条执行前告警决定，锁定后原子替换，超出删除，不生成历史备份。普通无告警、scan 和 PostToolUse 不记录。含规则、版本、策略指纹、决定来源、human_feedback、脱敏截断上下文和原因。有宿主调用 ID 时用哈希 operation_id 去重，不保存原 session/turn/tool-use ID。等待期间的 companion 条目不是人工批准；有效最终结果可替换该条目。

仅已启用规则能脱敏，未知敏感文本仍可能出现在上下文和原因中。Unix 新历史文件 0600、新建历史目录 0700；Windows 依赖用户目录 ACL。拒绝末端符号链接和非普通文件；已有目录权限不自动收紧。历史不可写时返回拒绝，不能承诺在磁盘故障时一定保存记录。导出副本和配置备份由用户管理，不受 100 条保留限制。

confirm 的无 UI、无效回复和超时按用户选择的告警继续策略处理；这是明确的宽松告警模式，不是强阻断。deny 规则仍阻断，不能由确认覆盖。客户端 decline/cancel、检查不完整及确认期间策略/脚本变化仍拒绝。拒绝是否生效取决于宿主尊重 Hook。两条路径并发时保留原生结果，缺少调用 ID 可产生重复但仍受 100 条上限约束。

同权限恶意进程能修改二进制、策略、Hook 或伪造客户端响应，不属于不可绕过边界。原生确认响应不构成针对恶意客户端的人工身份认证；标记的自动审批不会计为人工反馈，仍须实测宿主不同权限模式。只有有效 user 表单结果适合后续反馈分析，不自动改策略、不自动训练、不对外发送记录。

Prompt 可能已被宿主同步，PostToolUse 无法撤销副作用；托管工具及已有会话后续 stdin 可能没有新执行前 Hook。静态分析不是完整污点证明，检查后到执行前仍有时间窗口。没有端点网络隔离、管理员策略锁定或进程沙箱功能。

安装先校验再分别写 MCP TOML 与 Hook JSON，不是跨文件事务。备份完整包含原配置，可能有凭据，应妥善保存并清理。各桌面版本加载、原生表单、失败处理和操作系统签名仍需验收。[确认与记录](confirmation-history.md)、[验收](compatibility.md)。
